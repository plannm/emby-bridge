使用说明与注意事项

它到底做什么？安全吗？

它只做一件事：把你已有的播放器备份文件读进来，转换成另一种播放器认识的备份文件写出去。全部加解密都在你的浏览器里完成，页面通过 CSP 把 connect-src 设为 none，从浏览器层面禁掉了 fetch / XHR / WebSocket 等一切外联，因此绝不会去访问或登录你的 Emby 服务器，也就不存在触发服务器风控、封号的问题。页面不引用任何外部 CDN 资源，可离线使用。

典型用法：Windows 上导出 → Mac / 手机上导入

① 在 Windows 版 Rodel Player 的「设置 → 备份与恢复 → 其它应用」里，任选一个应用点「导出配置」，得到一个备份文件。
② 把这个文件传到 Mac / 手机（AirDrop、微信文件传输、网盘均可），在本网页「导入备份」里打开。
③ 检查、修改、去重，然后点目标播放器对应的导出按钮，把下载下来的文件交给目标 App 的「导入配置」即可。
也可以先导出「通用中间格式」长期保存；下次打开网页直接导入它，再转成任意播放器格式。

批量添加支持哪些写法？

点「批量粘贴 / CSV」，支持三种：
· CSV：表头为 name,type,url,username,password,userId,accessToken,icon,lines（可只写其中几列），线路列用 名称=地址|名称=地址 表示；
· 每行一台：名称 | https://地址 | 用户名 | 密码，分隔符也可用逗号、分号或制表符；只写 URL 也可以；
· 通用中间格式 JSON：本工具自己导出的文件。

各种格式有什么限制？

7 种播放器格式均已在本地用真实导出文件做过互转往返验证。AfuseKt 的明文结构里没有 User ID / Access Token 字段，转到该格式会丢失这两项，导入后需要重新登录一次；WWPlayer V1 是可逆混淆而非强加密，官方也提示应把 .wwpcfg 当作凭据文件保管。导出的备份里包含账号、密码与令牌明文（或等价的可逆数据），请勿上传到公开仓库、网盘分享链接或陌生网页。

部署到自己的域名 / GitHub Pages

index.html 是单文件，没有任何外部依赖：直接双击可用，或把仓库推到 GitHub 后在 Settings → Pages 选择主分支根目录即可；绑定自定义域名时加一条 CNAME 记录并在 Pages 里填写域名。建议开启 HTTPS（Web Crypto 在 HTTPS、localhost 和大多数浏览器的本地文件下可用）。页面不需要后端、不需要数据库、不需要 API Key。
